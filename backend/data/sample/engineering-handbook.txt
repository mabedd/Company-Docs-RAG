Engineering Handbook — Platform Team

Technology Stack
- Internal APIs are built with FastAPI (Python 3.11+) and deployed on Kubernetes.
- Frontend applications use React with TypeScript.
- Vector search and RAG experiments use ChromaDB for embeddings storage.
- Primary database: PostgreSQL 16. Cache layer: Redis.

Repository and Code Review
- All code changes require a pull request with at least one approval from a code owner.
- PRs must pass CI checks (lint, unit tests, security scan) before merge.
- Main branch is protected; direct pushes are not allowed.

Deployment
- Staging deploys automatically on merge to main.
- Production deploys require a release tag and approval from the on-call engineer.
- Rollbacks must be initiated within 30 minutes if error rates exceed 2% above baseline.

On-Call Rotation
- Each product team maintains a weekly on-call rotation.
- On-call engineers must acknowledge pages within 15 minutes.
- Incident severity definitions and escalation paths are documented in the runbook wiki.

Observability
- Services must emit structured JSON logs and Prometheus metrics.
- Distributed tracing uses OpenTelemetry; all new services must export traces to the shared collector.
- SLO target for customer-facing APIs: 99.9% availability per calendar month.

RAG and Internal Tools
- Document ingestion pipelines chunk text at 800 characters with 120-character overlap.
- Minimum relevance score for grounded answers is 0.15 in the default configuration.
- Mock LLM and embedding providers are used in local development; production uses OpenAI.

Testing Standards
- Unit test coverage target: 80% for new backend modules.
- Integration tests run against ephemeral databases in CI.
- Load tests are required before launching features expected to exceed 100 requests per second.
